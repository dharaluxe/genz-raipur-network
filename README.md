# GENZ Network

GENZ Network is a broker-first real-estate collaboration system for protected buyer introductions, master properties, broker-to-broker deals, visit proof and evidence-based reputation across India.

## V2 private beta

The V2 rebuild replaces the original monolithic pilot with separate Dashboard, Requirements, Properties, Broker Network and Deal Room modules.

The current private beta includes:

- invite-only broker membership with inviter/join audit and password reset
- Supabase authentication and shared multi-user PostgreSQL persistence
- buyer requirement registration with network-wide phone/source protection
- server-side HMAC phone fingerprinting with a database-private pepper
- 30-day buyer source-protection window
- masked buyer identity on network-visible requirement cards
- source-broker-only access to full buyer identity under Row Level Security (RLS)
- shared master property registration, duplicate checks and private owner identity vault
- explainable buyer-to-property matching by type, locality, budget and size
- broker directory with evidence-based Trust Score
- deal rooms restricted to the buyer-side and listing-side brokers
- proof timeline, collaboration acceptance, visit verification, offers and closure states
- closed-deal verified broker reviews
- property document / verification workflow
- nationwide property map and location pinning
- Realtime refresh for shared network records

## Phase 2.2

Phase 2.2 adds:

- separate invite-only Builder Portal memberships (`owner`, `admin`, `sales`), without creating broker profiles for builders
- privacy-safe builder-to-broker matching using aggregate protected-requirement counts; buyer names and phone numbers are never exposed to builders
- builder project invitations with broker accept/decline inbox
- owner-consent challenges with provider-independent secure link, crypto-random six-digit code, expiry and attempt limits
- public owner confirmation page that records consent to list, not legal title verification
- short-lived visit QR/check-in tokens; the issuing broker cannot self-verify
- optional on-site GPS evidence on QR visit verification
- Trust Score contribution from owner-confirmed listings, capped so inventory alone cannot dominate reputation
- dedicated Trust & Evidence, Owner Consent and QR Visit workspaces for brokers
- covering indexes for Phase 2.2 relationship keys used in invite, consent and visit workflows

Owner-confirmation delivery is provider-independent: the secure link and one-time code are generated by GENZ and can be shared manually. An SMS/WhatsApp provider can be attached later without changing the database model.

### Security boundary

GENZ network tables use RLS. Public network records contain only deliberately shareable fields; full buyer phone and owner identity are stored separately and are visible only to authorized roles. Deal-room participant identities are bound by database policy to the requirement source broker and property listing broker.

Builder accounts can manage only their own builder workspace. Builder matching returns aggregate requirement counts, not buyer identities. Project-invite state changes go through authorization-checking RPCs rather than direct client table updates. Visit check-in and owner-consent tokens are stored as hashes rather than plaintext.

The public owner-confirmation and invite-validation endpoints are intentionally token-gated; privileged network operations still require authenticated role checks inside their database functions.

The browser uses only the Supabase publishable client key. No service-role key or database-private phone pepper is exposed to the client.
